# 测试与验收清单

## 设备接入

- [ ] 小米：至少一台设备在 HA 中实体状态与实际一致，开关/模式/温度控制生效。
- [ ] 美的：至少一台设备在 HA 中实体状态与实际一致，开关/模式控制生效。
- [ ] 格力：至少一台设备在 HA 中实体状态与实际一致，开关/模式/温度控制生效。
- [ ] 三品牌原 App 仍可正常控制（备用通道）。

## 客户端

- [ ] 手机 HA App 在家用网络登录并控制成功。
- [ ] 手机 HA App 在移动网络（外网）登录并控制成功。
- [ ] 网页端登录成功。

## 语音

- [ ] "小爱同学，打开客厅空调"等指令对三家设备各测试至少一句。
- [ ] 语音控制后 HA 状态立即刷新。

## 自动化

- [ ] "一键全关空调"手动触发后三家空调全部关闭。
- [ ] 离家模式按预期触发。
- [ ] 定时任务按预期时间执行。

## 故障恢复

- [ ] `docker restart homeassistant` 后三个集成自动重连。
- [ ] 美居账号被踢后重新登录成功。
- [ ] 用 HA 备份 `.tar` 在临时容器完成一次恢复演练。
- [ ] 服务器重启后容器自动拉起。

## 安全

- [ ] 管理员账号已开启 2FA。
- [ ] 安全组仅放行所需端口。
- [ ] 确认 `config/`、`secrets.yaml` 等敏感内容未提交 git。

## 小爱音箱基础包

- [ ] 对小爱说“我回来了”，约 5 秒内音箱播报“欢迎回家”。
- [ ] 对小爱说“我出门了”，全屋空调与电视关闭，音箱播报确认。
- [ ] 对小爱说“晚安”，电视关闭、音箱道晚安。
- [ ] 洗衣机完成一次洗涤（运行超过 5 分钟），音箱播报“衣服洗好了”且手机收到通知。
- [ ] 仅开机（不启动程序）或仅开关机：不应播报。
- [ ] 启动后 5 分钟内取消：不应播报。
- [ ] 次日 07:30 早间播报正常（若错过，可手动把触发时间临时改到 2 分钟后验证）。
- [ ] 人工测试时注意：关键词匹配可能误触发（如“我走了”），误触发则调整关键词列表。

## AI 家庭管家

- [ ] 先确认 DeepSeek Conversation 已配置 API Key；未配置或服务不可用时，小爱不重复播报、也不播报错误内容。
- [ ] 小爱回答“不知道”“不清楚”“没有答案”“暂不支持”“没听懂”等失败答复后，分别询问“客厅空调开着吗”“洗衣机洗完了吗”“家里温度多少”，每次仅播报一次、内容不超过两句。
- [ ] 在 10 分钟内连续追问一次，回答保持当前话题；超过 10 分钟后再次提问，不引用先前对话。
- [ ] 对小爱说“晚安”“我出门了”“关闭空调”等已有指令，确认仍由原自动化处理，AI 不参与。
- [ ] 请求控制设备时，确认 AI 仅提示需要确认，不改变任何设备状态。
- [ ] 将任一状态实体临时设为不可用（或在开发者工具模拟）后，回答应为“暂时无法确认”，不得猜测。
- [ ] 在 DeepSeek Conversation 选项中确认 `include_user_context` 已关闭、Home Assistant API 未选择；检查公开发布副本不含 API Key、地址、坐标或设备标识。
